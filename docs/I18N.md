# Languages (i18n)

VILauncher speaks **English** (`en`, the source), **Traditional Chinese** (`zh-TW`) and
**Simplified Chinese** (`zh-CN`).

## Which language is shown

1. The player's choice in **Settings → Appearance → Language**, saved as `language` in
   `%APPDATA%\VILauncher\settings.json` (`null`: follow the system).
2. Otherwise the system's: the window sends `navigator.languages` at start
   (`set_system_languages`), and the first one VILauncher speaks wins. `zh-TW`, `zh-HK`,
   `zh-MO` and `zh-Hant-*` mean Traditional Chinese; other `zh` tags Simplified.
3. Otherwise English.

The launcher decides (`src-tauri/src/i18n.rs`, `resolve`) and sends the result as the
snapshot's `locale`; the window follows it. Before the first snapshot the window uses the
language it last showed on this PC, so it doesn't flash English.

## What is translated, and what stays as it is

Translated: everything VILauncher itself says in the window: labels, buttons, dialogs,
the legal notice, warnings, toasts, the job's stage, and the launcher's errors.

Not translated, on purpose:

- **Project content**: names, summaries, highlights and blockers from the tracker, and the
  player's own notes. They are their authors' words.
- **Logs**: the Activity log, `logs\<slug>.log`, problem reports (GitHub issues) and the
  `--fix` / agent tool output stay English, the language of Git's and Cargo's output and of
  the maintainers who read the reports. The launcher's own messages are English inside the
  launcher and are translated only on their way into the window.
- Names: VILauncher, VIPortLive, VIctory, PortWatch, GitHub, Git, Rust, winget, file names,
  commands, environment variables (`VICTORY_NAME=value`), and units (GB, fps).

## The window (TypeScript)

Messages live in `src/i18n/messages/<locale>/<namespace>.ts`, one namespace per part of
the window (`common`, `shell`, `dialogs`, `legal`, `library`, `settings`, `format`).
English is the source (`as const`); every other language is `satisfies Translation<typeof en>`,
so a missing, extra or misplaced key is a **type error**.

```tsx
import { Trans, useT } from "@/i18n"

function Example({ count, path }: { count: number; path: string }) {
  const t = useT() // re-renders when the language changes
  return (
    <>
      <h2>{t("settings.language.label")}</h2>
      <p>{t("library.projects", { count })}</p>
      <Trans k="dialogs.import.where" values={{ path }} tags={{ code: (s) => <code>{s}</code> }} />
    </>
  )
}
```

- `t(key, params)`: keys and their `{placeholders}` are checked by TypeScript. Numbers are
  written the language's way (pass a string for ids and years). Outside components (stores,
  toasts, `api.ts`) import `t` itself.
- **Plurals**: `{ one: "{count} project", other: "{count} projects" }` in English; the form is
  picked for `count` with `Intl.PluralRules`. Chinese gives only `other`. Because of this, a
  group of messages must not have a key named `other` (or `zero`, `one`, `two`, `few`,
  `many`): it would be read as plural forms.
- **Markup**: `<code>…</code>`, `<b>…</b>` or `<link>…</link>` inside a message, drawn by
  `<Trans tags={…}>`. Never split a sentence into several messages to put markup between
  them: word order differs between languages.
- `formatNumber`, `formatBytes`, `formatList` (`"a, b and c"` / `"a、b和c"`).
- Lists of options (graphics modes, themes) keep their ids in code and look up their labels
  with `t` when drawn.
- `pnpm i18n:check` (also in CI and `pnpm ci:check`) compares every language with English
  (keys, placeholders, tags, plural forms, empty messages) and finds English still written in
  the UI code: JSX text, UI attributes (`aria-label`, `label`, `hint`, `placeholder`,
  `title`…), toasts and sentences. For text that must stay as it is, write `// i18n-ignore`
  on its line or the line above. `src/dev/mock.ts` is not checked: it stands in for the
  launcher, whose messages are English.

## The launcher (Rust)

A message for the player is written in English where it is made, and marked:

```rust
return Err(msg!("Could not delete the save: {e}"));        // format!, marked
j.stage = msg_str!("Installed: ready to play").into();     // &'static str, marked
```

`msg!` is `format!`; `msg_str!` is the literal itself. Inside the launcher both are plain
English. They are translated where they cross into the window, with `i18n::localize`:
the snapshot (`launcher/view.rs`), an action's error (`main.rs`, `act`) and text inside an
action's answer. `localize` finds the message in the catalog, also when it has values in
its placeholders (`Could not delete the save: Access is denied.`), and translates values
that are messages themselves (`Install failed: {error}`). Text it doesn't know (a path, an
OS error, Git's output) is shown as it is.

Catalogs: `src-tauri/locales/<locale>/*.json`, from the English message (placeholders as
`{name}`, format specs dropped, `{}` numbered `{0}`, `{1}`…) to the translation:

```json
{ "Could not delete the save: {e}": "無法刪除存檔：{e}" }
```

`cargo test` checks that every `msg!` / `msg_str!` in `src/` has a translation in every
catalog with the same placeholders, and that no catalog keeps a message the code no longer
has. Give placeholders names that say what they hold (`{path}`, `{error}`), never put two
placeholders side by side, and don't build a message from pieces that are translated apart.

## Adding a message

1. Window: add it to `src/i18n/messages/en/<namespace>.ts`, then to the same file in every
   other language (TypeScript lists what is missing), and use it with `t`.
2. Launcher: write it with `msg!` / `msg_str!`, and add it to each `src-tauri/locales/*/<area>.json`
   (`cargo test` lists what is missing). If it reaches the window by a new route, pass it
   through `i18n::localize` there.

## Adding a language

1. `src/i18n/locales.ts`: add the tag to `LOCALES`, its own name to `LOCALE_NAMES`, and to
   `matchLocale` if its tags need mapping.
2. Copy `src/i18n/messages/en` to `src/i18n/messages/<tag>`, translate it, make each file
   `satisfies Translation<typeof en>` as the Chinese ones do, and add it to `CATALOGS` in
   `src/i18n/index.tsx`.
3. `src-tauri/src/i18n.rs`: add it to `Locale` (`ALL`, `tag`, `matching`); copy a Chinese
   folder of `src-tauri/locales` to `src-tauri/locales/<tag>`, translate it, and list its
   files in `CATALOG_FILES`.
4. If its script needs other fonts, add them to `--font-cjk` (or a new variable) in
   `src/styles.css` under `:root:lang(<tag>)`.
5. Translate `LEGAL.md`'s notice in the `legal` namespace, keeping its English version as
   the one that governs.
6. Translate `README.md` as `README.<tag>.md` and add it to the language links at the top
   of every README (see [The README](#the-readme)).
7. `pnpm ci:check`.

## The README

`README.md` is English and the one that governs. `README.zh-TW.md` and `README.zh-CN.md`
are its translations: the same sections in the same order, the same images and links, with
the images' alt text translated. A line of links under the banner switches between them;
the current language is bold, not a link.

- When you change `README.md`, change both translations in the same pull request, or say in
  it that they still need it.
- The other documents (`LEGAL.md`, `CONTRIBUTING.md`, `docs/`) are English only. A
  translation marks a link to one with （英文）.
- Keep names, commands, paths and code as they are; translate comments in code blocks.
- Bold in Chinese: end the bold text before its punctuation (`**不含任何遊戲**。`, not
  `**不含任何遊戲。**`), or GitHub shows the asterisks.
- Use the terms in the table below, so the README says what the window says.

## Style for the Chinese translations

- Short, plain interface wording; address the player as 你 (not 您).
- Full-width punctuation in Chinese text: ，。：；！？（）. Quotes: 「」 in zh-TW, “” in zh-CN.
  Keep the ellipsis `…`.
- A space between Chinese and Latin letters or digits: `3 天前`, `GPU 管線`, `C++ 建置工具`.
- Same term everywhere:
