# Security Policy

## Reporting a vulnerability

Please **do not** open a public issue for a security problem. Report it privately:

- Use GitHub's **Report a vulnerability** button on the repository's Security tab (private vulnerability reporting), or
- contact the maintainers through the private channel listed on the repository's profile.

Include what you found, the version (shown in Settings → About), steps to reproduce, and what an attacker could do. We aim to acknowledge a report within a week and to tell you what we plan before anything is published.

## What counts

- A way for a project, an imported repo, a ZIP or a web page to act beyond what the player agreed to (for example, changing files outside the project's folder, reading saves, or running code without the warning).
- A way to bypass the AI-agent access setting or its confirmations.
- Leaking personal data, or private paths, through the launcher, its logs or its reports.
- Tampering with the launcher's own updates or downloads (the launcher checks SHA-256 digests).

## What does not count

- A project's own bugs or security issues. Report those to that project's authors.
- Problems that need a computer already controlled by the attacker.
- Game content questions. See [LEGAL.md](LEGAL.md).

## Supported versions

Only the latest release receives security fixes.
